# Mathematical and computational modelling of embryonic organoids

![Language: Julia](https://img.shields.io/badge/language-Julia-ed207b)
![Jupyter Notebook](https://img.shields.io/badge/Notebook-Jupyter-f37821)

Agent-based model of gastruloid squeezing, built on
[CellBasedModels.jl](https://github.com/dsb-lab/CellBasedModels.jl).

A single set of mechanical parameters reproduces three observations:

* **fusion** of two aggregates of pure cell type — in particular B–C *glues*
  instead of rounding into a sphere;
* **polarisation** of an unconfined aggregate with an A,B core;
* **patterns**: squeezed between plates, the A,B mass breaks into islands in a
  C sea, above a critical initial cell number that grows with the thickness.

See **[REPORT.md](REPORT.md)** for the parameter set, the results and the
caveats.

## Layout

```
code/
  squeezing-gastruloids.ipynb   the notebook: model, parameters, analysis
  Project.toml, Manifest.toml   pinned environment
  scripts/
    gastruloids_lib.jl          EXPORTED from the notebook -- do not edit
    export_lib.ps1              re-export it after editing the notebook
    set_cell.ps1                replace one notebook cell from a .jl file
    run_phase_map.jl            the layers x N0 scan (resumable)
    run_checks.jl               polarisation / wall equivalence / fusion assay
    make_figures.jl             figures from saved trajectories
    make_report.jl              REPORT.md from results/phase_map.csv
  results/
    phase_map.csv               one row per run
    coms/*.jld2                 saved trajectories (array format)
  figures/                      generated figures
```

`code/results/` and `code/coms/` are gitignored — they are regenerated by the
scripts.

## Setup

```julia
using Pkg
Pkg.add(url = "https://github.com/dsb-lab/CellBasedModels.jl")
```

then, from the repository root:

```bash
julia --project=code -e 'using Pkg; Pkg.instantiate()'
```

`code/Project.toml` and `code/Manifest.toml` are a snapshot of the environment
these results were produced in. If you would rather install by hand:

## Reproducing the results

```bash
# the phase map -- resumable, several hours
julia -t auto --project=code code/scripts/run_phase_map.jl

# polarisation, wall-setting equivalence, fusion assay
julia -t auto --project=code code/scripts/run_checks.jl all

# figures and the report
julia --project=code code/scripts/make_figures.jl
julia --project=code code/scripts/make_report.jl
```

`run_phase_map.jl` appends to `code/results/phase_map.csv` and skips points
already present, so it can be interrupted and restarted.

## Working in the notebook

`scripts/gastruloids_lib.jl` is generated from the notebook, so the notebook is
the single source of truth. After editing a function cell:

```bash
cd code && powershell -File scripts/export_lib.ps1
```

The notebook has grown past what some editors will diff comfortably; to replace
one cell from a plain `.jl` file (with a backup and a check that no other cell
changed):

```bash
cd code && powershell -File scripts/set_cell.ps1 -CellId 4cd7bbef -SourceFile mycell.jl
```

## A note on saving runs

`jldsave("com.jld2"; com)` does **not** round-trip. `ABM()` evaluates the
generated step functions as anonymous closures in `Main`, and the pickled
`Community` references them by gensym name, so reloading in a different session
fails with

```
MethodError: Cannot `convert` an object of type
             JLD2.ReconstructedSingleton{Symbol("#19#20")} to ... Function
```

Use `save_frames` / `load_frames` (plain arrays) instead. They load in any
session with the model not even defined, and are ~7× smaller.
